# Vibe Downloader 功能增强与扩展建议

整理日期：2026-09-21  
适用基线：Vibe Downloader `0.5.0`，包含当前工作区未提交修改。  
文档性质：功能规划建议。文中的首版范围、行为和验收目标均为建议方案，不代表已实现或已排期。

关联文档：[四维现状审查](project-review-2026-09-21.md) · [既有功能与页面构想](feature-and-page-proposals.md) · [主审计](project-improvement-audit.md) · [路线图](ROADMAP.md) · [产品约束](../PRODUCT.md) · [设计约束](../DESIGN.md)

## 1. 规划目标与当前基础

本建议面向三类日常场景：重复创建下载任务、集中管理大量文件、恢复成本较高的大文件下载。目标是减少重复配置、降低失败损失，并让用户能够理解和控制下载过程。

项目已经有任务优先级、逐任务限速与代理、分类和站点规则、批量传输动作、全局计划窗口、恢复中心、存储与清理中心、备份与迁移中心、完整性护照及任务时间线。这些是下述建议的基础，不应重新包装成尚未实现的功能。浏览器集成中心的新增后端与完整用户入口仍需区分，详见现状审查 `R26-F10`。

本文收录 **15 项**功能方向，编号 `FE-01`～`FE-15` 仅用于本文件。它们不属于主审计的问题 ID，不改变任何既有条目的 Open／Partial／Closed／Boundary 状态。现状审查中的 `R26-*` 是该报告的局部发现编号，实施前仍需重新核对并在主审计中确认需要跟踪的问题。

优先在现有新建窗口、列表工具栏、详情页、队列中心和设置中增加能力，保留密集、安静的桌面工具布局。只有需要独立处理流程时才增加页面，避免每项功能都变成新的一级导航。

## 3. 近期增强

### FE-01：任务预设

**当前基础：** 新建流程已有共享草稿模型，覆盖分类、优先级、限速、代理、认证与校验字段；站点规则和分类规则已有独立管理及试运行。缺少的是可命名、可复用的任务配置集合。依据：[create-draft.ts](../src/lib/create-draft.ts)、[NewDownloadDialog.tsx](../src/components/shell/NewDownloadDialog.tsx)。

**适用场景：** 用户经常下载模型、系统镜像、软件包，分别使用不同目录、优先级和限速，每次都需要重复配置。

**具体能力：** 新建、复制、重命名和删除预设；从当前任务复制非敏感配置；在新建和批量窗口选择预设后显示有效配置，并允许本次覆盖。后续可让规则选择预设。

**用户收益：** 减少创建前的输入与遗漏，让常用设置成为明确、可检查的操作选择。

**首版范围：** 仅手动选择命名预设，保存目录、分类、优先级、逐任务限速和非敏感代理配置。首版不保存密码、Cookie、私钥、URL token、任意命令或固定文件摘要；具体文件的预期 hash 仍逐任务输入。选择预设时显示将替换的字段；用户随后编辑优先，切换预设前提示覆盖差异。预设修改只影响之后应用的任务。

**实现依赖：** 草稿状态隔离、统一探测上下文及配置校验；提供版本化预设存储与类型化 IPC。保留继承／关闭／自定义代理的现有含义，导出预设必须清除 URL 中潜在机密。扩展字段不能绕过现有创建命令。

**复杂度估计：中。** UI 与存储工作量适中，主要成本是预设、规则、手动覆盖和敏感字段边界的一致性。

**验收标准：** 保存后重启可恢复；单任务和批量应用结果一致；修改预设不改变已创建任务；手动覆盖可解释；无效目录／代理能定位错误；导出与日志不包含机密。基于新建实际参数验证，不只断言表单显示。

### FE-02：更换失效下载链接

**当前基础：** 已有远端验证、断点续传、结构化恢复动作，以及浏览器重新交接更新过期 headers 的路径。为同一任务替换不同 URL 并安全复用已有字节，是独立能力，不能等同于现有 header 刷新。依据：[task_resume.rs](../src-tauri/src/commands/task_resume.rs)、[recovery.rs](../src-tauri/src/commands/recovery.rs)。

**适用场景：** 大文件已经下载大半，临时链接过期；用户从原站点重新取得链接，希望保住已有数据。

**具体能力：** 在恢复动作中输入新链接，展示新旧资源的大小、可恢复性、身份校验依据与最终处理结果；通过验证后更新任务来源并继续。失败时保留原记录和文件，给出从头下载的独立选择。

**用户收益：** 降低临时链接失效带来的时间、流量损失，减少重新建立任务和整理文件的成本。

**首版范围：** 仅暂停或失败的 HTTP／HTTPS 单文件任务。先排空任务运行时，再探测和决定是否替换。只有可信内容标识、可核实的原资源验证关系或分片校验等足够证据允许保留字节；文件名和长度相同不构成证明，不同资源／源域上相同的 ETag 文本也不能直接视为相同文件。无法确认时明确提供重新下载，不静默拼接。旧 URL 的 Cookie、Authorization 和代理凭据不自动跨源继承。

**实现依赖：** 统一认证／代理／SSRF 探测路径、每任务锁和暂停收敛、远端身份模型、事务化来源更新。实施前复核现状审查 `R26-F01`、`R26-A01` 等关联路径；不能将后端表中的 URL 简单替换视为功能完成。

**复杂度估计：高。** 难点在资源身份和恢复正确性；一个“编辑 URL”输入框只是入口。

**验收标准：** 同资源新签名链接在满足验证条件时续传成功；同大小不同内容必须拒绝不安全复用；不支持 Range、旧凭据跨源、探测失败和替换中断均有明确结果；失败不改变原文件；并发恢复／删除不会产生双 worker；完成文件逐字节或可信摘要验证通过。

### FE-03：批量编辑任务配置

**当前基础：** 已有多选、批量暂停／恢复／重试，以及单任务优先级、限速、分类、代理等配置。缺少统一的多任务属性编辑。依据：[actions.rs](../src-tauri/src/commands/tasks/actions.rs)、[TaskDetails.tsx](../src/components/shell/TaskDetails.tsx)。

**适用场景：** 同时给几十个任务降速、改为低优先级，或把一批任务归入同一分类。

**具体能力：** 多选后显示共同值和混合值，选择要改变的字段，预览受影响范围，再返回成功／跳过／失败明细，并支持仅重试失败项。

**用户收益：** 减少逐个打开详情修改的操作；遇到部分失败时仍能准确知道哪些任务已生效。

**首版范围：** 优先级、逐任务限速、分类、是否遵循计划窗口；代理作为后续扩展，移动目录交给 FE-06。每个字段明确区分“不修改”“设置值”“清除／恢复默认”，不能把未填写字段解释成清空。第一版针对显式选择的任务 ID；选择筛选全集后续使用服务端确认的任务集合。

**实现依赖：** 新增明确的批量 patch 合同与逐项结果模型，复用现有状态门和配置校验。现有单任务接口对不同可选字段的缺省处理并不完全相同，不能直接逐次调用并假设所有省略字段都保持不变。大量任务需要分页或分块处理，取消后保留已完成结果。

**复杂度估计：中。** 主要成本是字段语义、状态变化与部分成功反馈，而不是批量按钮本身。

**验收标准：** 混合状态的 100 个任务仅变更选定字段；未编辑的限速／分类保持不变；非法输入在提交前被指出；处理过程中任务完成或被删除时正确跳过；取消与失败不抹掉已经生效的结果；运行时生效方式与单任务配置一致。

### FE-04：保存常用筛选视图

**当前基础：** 已有搜索、导航状态、文件类型、来源、失败原因、续传条件和排序，UI store 没有命名查询集合。依据：[task-ui-store.ts](../src/stores/task-ui-store.ts)、[task-query.ts](../src/stores/task-query.ts)。

**适用场景：** 用户每天查看同一站点的失败任务，或者反复切换几个固定的下载集合。

**具体能力：** 保存当前查询为命名视图，重命名、复制、删除和快速应用；显示查询条件摘要，并可返回全部任务。后续再增加相对日期、大小和校验状态筛选。

**用户收益：** 把重复设置条件变成一次点击，也方便建立个人的日常检查习惯。

**首版范围：** 仅保存后端当前实际支持的查询条件及排序。视图是动态查询，不复制任务，不保存选中 ID、分页 cursor 或过期列表结果。“本周失败”“大于 1 GiB 且未校验”等更丰富视图，需要先扩展对应后端查询能力，不能仅增加一个名称。

**实现依赖：** 版本化查询配置与兼容读取、切换时的请求版本校验和分页重置。不能通过一次性加载全数据库后在前端过滤实现保存视图。保存的搜索文本可能包含敏感链接，导出时沿用脱敏规则。

**复杂度估计：低。** 复用已有查询路径；成本估计不包含新增筛选维度、跨设备同步或全集操作。

**验收标准：** 重启后视图仍在；新任务和状态变化能动态反映；快速切换不被旧响应覆盖；不同语言下配置含义一致；删除视图不删除任务；升级遇到未知字段时提供可解释的兼容处理。

### FE-05：磁盘空间预算

**当前基础：** 存储中心已有按保存目录的磁盘概览、artifact 清单和安全清理；引擎已有临时文件／staging 与写入错误处理。跨任务的预计峰值空间和调度预算是新增增强。依据：[storage.rs](../src-tauri/src/commands/storage.rs)、[artifacts.rs](../src-tauri/src/download/artifacts.rs)、[scheduler/mod.rs](../src-tauri/src/scheduler/mod.rs)。

**适用场景：** 同时下载大型镜像、模型或视频，目标盘剩余空间看似够放成品，却无法容纳并行任务及转封装临时文件。

**具体能力：** 显示当前剩余空间、任务尚需空间、预计额外峰值和同卷已承诺预算；开始任务前检查，运行期间定期复核；空间不足时暂停相应任务，并引导用户清理或稍后重试。

**用户收益：** 在大量数据写入前发现不足，降低下载和 remux 临近结束时失败的概率。

**首版范围：** 先覆盖已知长度 HTTP／HTTPS 单文件；预算按磁盘卷聚合，避免同一卷不同目录重复计算可用空间。区分已实际占用、预分配／稀疏文件、剩余下载量和跨卷发布额外空间。未知长度任务标为未知并执行剩余空间阈值监控；HLS／DASH 等有阶段峰值的协议先显示能力边界，再逐引擎提供估算。应用内预算无法阻止其他程序占用磁盘。

**实现依赖：** 按卷资源账本、平台空间查询、引擎空间估算合同、调度前原子预算占用与退出释放。空间暂停需独立原因，释放空间后不得擅自恢复用户手动暂停的任务。暂时无需在前端增加另一套调度器。

**复杂度估计：高。** 主要成本是多任务竞争、预分配口径、跨卷发布以及异常退出后的预算重建。

**验收标准：** 两个目录位于同一卷时共享预算；多个任务不会分别通过检查后过量承诺；下载成功／取消／失败／重启后账本可恢复；外部进程耗尽磁盘时及时暂停且保留断点；空间查询失败显示未知；协议不支持精确估算时不展示虚假精确数值。

### FE-06：文件位置管理

**当前基础：** 任务持久化最终路径，已有打开文件／目录、名称冲突处理、存储检查及备份路径重映射。日常完成文件的重命名、移动和重新关联，需要独立的文件操作流程。依据：[file_ops.rs](../src-tauri/src/download/file_ops.rs)、[task_file_planning.rs](../src-tauri/src/commands/task_file_planning.rs)。

**适用场景：** 用户将已下载文件归档到其他盘，或在文件管理器中移动后，任务记录中的打开入口失效。

**具体能力：** 完成后重命名和移动到新目录；文件缺失时由用户重新定位；验证关联后更新路径；无法找回时创建明确的重新下载操作。

**用户收益：** 下载记录能长期作为查找和校验入口，减少“列表显示完成，文件却找不到”的困惑。

**首版范围：** 仅单个已完成、没有活动 writer／校验／做种占用的普通文件。多文件目录、BT 做种期间迁移和正在下载的临时文件搬迁延期。跨卷采用复制、验证、发布、更新记录后再清理旧文件；重新定位若缺乏可信 hash，只能显示用户确认关联，不能升级为已验证。

**实现依赖：** 原子拒绝覆盖、路径所有权、可恢复操作记录与磁盘预算。实施前复核现状审查 `R26-A01`；持久化路径与文件系统修改需要补偿和重启恢复，单次数据库事务不能原子覆盖两者。

**复杂度估计：高。** 难点在外部文件竞争、跨卷、系统占用以及操作中途退出。

**验收标准：** 同卷／跨卷移动和重命名成功后，打开／校验入口正确；目标冲突不覆盖外部文件；权限拒绝、磁盘满、进程退出和 DB 更新失败时至少保留一个完整文件；错误关联不显示校验通过；旧路径清理失败单独报告。

## 4. 后续扩展

### FE-07：任务分组／下载集合

**当前基础：** 已有分类、筛选、多选和批量动作，但分类标签并不等同于一个具有成员与整体进度的下载集合。依据：[task-data-store.ts](../src/stores/task-data-store.ts)、[QueueCenter.tsx](../src/components/workspaces/QueueCenter.tsx)。

**适用场景：** 一个模型由多个权重文件组成，或者一个数据集包含上百个独立下载链接，用户希望将它们作为一次工作管理。

**具体能力：** 创建命名集合、增减任务成员、查看整体状态和进度，统一暂停／恢复／重试。后续再增加集合级限速与完成流程。

**用户收益：** 用户按“模型 A”“本次课程资料”操作，不必反复查找并选中成员。

**首版范围：** 非嵌套集合，一个任务最多属于一个集合；分类继续表达文件用途。仅提供组织、汇总与已有批量传输动作。移除集合保留任务，删除成员文件仍走单独确认。未知大小成员单列，不能将已知成员下载完毕显示成整个集合 100%。

**实现依赖：** 持久化集合及成员关系、复用批量操作结果、分页汇总。后续若实现集合限速，需要共享总量预算，给每个成员设置同一个限速数值并不等于集合总限速。

**复杂度估计：中。** 估计针对首版组织能力；总量限速、依赖顺序和分组完成流程会增加成本。

**验收标准：** 创建／重启／成员删除后的集合一致；成员状态改变及时反映；包含失败或未知大小任务时汇总诚实；批量部分成功可追溯；删除集合不会隐式删除文件。

### FE-08：精细计划下载

**当前基础：** 已有全局下载窗口、限速窗口、逐任务是否遵循计划、优先级和延迟重试。增强方向是逐任务和多个周期窗口。依据：[AppSettings](../src-tauri/src/models/task.rs)、[scheduler/mod.rs](../src-tauri/src/scheduler/mod.rs)。

**适用场景：** 某任务今晚开始，另一些仅工作日凌晨运行；用户希望在界面上看到下次开始时间和等待原因。

**具体能力：** 一次性开始时间、按星期重复的允许下载窗口、多个不重叠时间段；计划预览和冲突说明。后续可以应用到集合。

**用户收益：** 按实际生活与网络使用安排任务，降低每天手动暂停／恢复的成本。

**首版范围：** 计划只控制已有任务何时有资格运行，不自动产生重复下载。一次性时刻持久化为明确的时间点；周期窗口保存时区并显示下次运行。任务窗口与它所遵循的全局窗口取交集，仍受资源／主机槽限制。睡眠错过窗口后重新计算资格，不补跑已经过期的时间段；手动暂停保持有效。

**实现依赖：** 统一计划判断、持久化调度唤醒与暂停原因、时区处理。补齐跨午夜、夏令时跳过／重复时刻的确定行为；所有窗口变化复用当前 scheduler。

**复杂度估计：高。** 时间、休眠唤醒、全局与任务规则叠加，比增加一个日期输入框复杂。

**验收标准：** 跨午夜、跨星期、系统时钟变化、时区变化、夏令时边界及重启后得到正确的下一次资格；窗口结束能安全暂停；手动暂停不被计划覆盖；同一任务不会重复派发；UI 等待原因与后端一致。

### FE-09：网络与电源策略

**当前基础：** 已有全局／逐任务限速、优先级、并发限制、网络重试和启动恢复。部分 HTTP 重试已遵循 Retry-After，新增策略应复用这些保证。依据：[scheduler/mod.rs](../src-tauri/src/scheduler/mod.rs)、[speed.rs](../src-tauri/src/download/speed.rs)、[HTTP worker](../src-tauri/src/download/http/segmented/worker.rs)。

**适用场景：** 笔记本改用热点、网络频繁断开，或拔掉电源后希望降低下载负担。

**具体能力：** 工作网络／移动网络／省电等策略预设；网络恢复时分批唤醒任务；后续按各平台可靠提供的计费网络或电源事件自动切换。

**用户收益：** 控制带宽和电量，减少恢复网络后所有任务同时重连的冲击。

**首版范围：** 用户手动切换配置策略，显示最终并发、限速、是否接纳新任务及影响范围；先实现可靠的离线恢复编排。自动计费网络识别按平台分阶段上线，无法识别时显示未知，不把 SSID 当成可信网络证明。不更改 OS 网络设置或悄悄替换任务的显式代理选择。

**实现依赖：** 平台事件适配、暂停原因记录、带抖动的恢复队列、限速器生命周期与取消收敛。启用长期自动策略前复核 `R26-P01`；因认证或远端变化失败的任务不能按“网络恢复”自动重试。

**复杂度估计：高。** 手动预设本身可分步实现，跨平台自动感知及并发恢复需要额外验证。

**验收标准：** 网络反复通断不产生双任务和无限重试；遵循服务端 Retry-After；只恢复符合条件的系统暂停任务；用户手动限速与代理覆盖关系可见；平台事件不可用时仍能手动控制；多轮切换无 ticker／监听器泄漏。

### FE-10：批量链接生成与命名预览

**当前基础：** 已有多行 URL 文本、文本文件导入、去重、探测和批量创建。新增能力是生成规则、逐行名称和完整预览。依据：[NewDownloadDialog.tsx](../src/components/shell/NewDownloadDialog.tsx)、[create.rs](../src-tauri/src/commands/tasks/create.rs)。

**适用场景：** 下载 `part001`～`part100` 等连续编号资源，或从表格粘贴 URL 和期望文件名。

**具体能力：** 展开一个数值区间，保留补零；粘贴两列“URL＋文件名”；批量命名预览；显示非法行、批内重复、已有任务与最终名称冲突。

**用户收益：** 减少手动拼接 URL 和逐个重命名，创建之前就能发现错误。

**首版范围：** 单一数值区间、正步长、最多 1000 行展开，以及制表符分隔的两列输入；普通 URL 不自动解析为模板，用户明确进入生成模式后才展开。提交前必须预览；生成并不证明 URL 存在。先支持名称的固定前后缀和序号，不引入任意表达式执行。

**实现依赖：** 先复核并处理现状审查 `R26-U02`／`R26-U03` 的结果与并发问题，复用后端文件名规范化和去重策略。预览应虚拟化或分页，探测限并发、可取消，避免一次展开触发大量无界请求。

**复杂度估计：中。** 规则本身较小，完整的预览、错误定位、取消和部分成功处理是主要工作。

**验收标准：** 补零、反向区间、零步长、越界和超过上限可正确处理；URL query 中普通花括号不被误展开；文件名不能造成目录穿越；第 6／500／1000 条失败均能查看与重试；取消后成功任务保留且不会重新批量创建。

### FE-11：下载瓶颈解释

**当前基础：** 已有请求、连接、分片、日志、速度历史、队列原因和协议诊断面板。统一的用户可理解解释可以利用这些数据，但磁盘／网络细分延迟等额外指标需要真实采集。依据：[task-diagnostics.ts](../src/lib/task-diagnostics.ts)、[TaskDetails.tsx](../src/components/shell/TaskDetails.tsx)、[query.rs](../src-tauri/src/commands/tasks/query.rs)。

**适用场景：** 用户看到速度很低，不知道应该增加连接、检查代理、调整限速还是等待服务器。

**具体能力：** 显示一个主要原因、证据时间与可执行建议；区分确定事实和推测，例如“任务限速为 2 MiB/s”“主机连接槽已满”“最近多次收到 429”。

**用户收益：** 降低阅读原始日志的门槛，减少无效地增加并发、重复重试或更换配置。

**首版范围：** 只解释已有可信证据能证明的限速、等待窗口、主机槽、Range 不支持、明确的 HTTP 状态与最近重试。不依据速度下降单独断言“服务器限速”或“磁盘瓶颈”；没有测量依据时显示未知或列出检查建议。后续通过有界采样增加 DNS／建连／首字节／磁盘等待指标。

**实现依赖：** 后端结构化原因和参数、有效期、采样上限、前端本地化映射；详情与总览共用同一解释模型。诊断不能产生高频轮询或保留敏感请求头，先复核 `R26-P04` 的剩余轮询路径。

**复杂度估计：高。** 首版可分步覆盖确定性解释，完整瓶颈定位的成本在数据质量与误判控制。

**验收标准：** 本地 fixture 分别制造限速、槽位耗尽、429、读超时和无 Range，解释与证据一致；证据过期后不继续显示实时结论；未知场景不生成假原因；语言切换正确；隐藏面板时不维持高频采样。

### FE-12：完成后处理流程

**当前基础：** 已有校验、系统通知和队列完成动作，包括可取消退出、确认关机和用户配置命令。新增方向是可查看、可恢复的逐任务／分组处理阶段。依据：[scheduler/mod.rs](../src-tauri/src/scheduler/mod.rs)、[checksum.rs](../src-tauri/src/download/checksum.rs)、[task.rs](../src-tauri/src/models/task.rs)。

**适用场景：** 大文件完成后需要校验、移到归档目录并通知；用户希望失败时仅重试后处理，不重新下载。

**具体能力：** 配置固定顺序的“校验→归档移动→通知”，分别展示阶段结果和耗时；后续与任务预设、集合完成规则结合。

**用户收益：** 减少重复归档操作，同时分清网络下载成功与后处理失败。

**首版范围：** 内置动作组成的线性流程，首先支持普通完成文件。校验失败停止后续归档；通知失败不回滚已验证文件；重试从失败阶段开始。先不引入任意脚本工作流、自动运行安装包或通用解压；现有用户命令能力不自动成为所有任务的默认动作。

**实现依赖：** FE-06 的可靠移动、持久化阶段状态、取消与幂等、校验作业预算。队列完成动作必须等待需要完成的校验／归档阶段，不能因网络传输归零就关机；保留已关闭 `ARC-46` 的完成时序保证。

**复杂度估计：高。** 主要成本是阶段恢复、重复执行控制、文件操作与关机时序。

**验收标准：** 下载成功但校验／移动失败时保留正确状态并允许局部重试；中途退出后已完成移动不会重复执行；归档目标冲突无覆盖；关键处理尚未结束不触发关机；通知可抑制，机密不进入流程日志。

## 5. 中长期能力

### FE-13：定期资源检查

**当前基础：** 已有资源探测、远端验证、任务创建、去重和计划窗口，但计划窗口只控制下载时机，不等于资源更新订阅。依据：[HTTP probe](../src-tauri/src/download/http/probe.rs)、[create.rs](../src-tauri/src/commands/tasks/create.rs)。

**适用场景：** 定期检查固定地址上的数据集、规则包或发布清单，希望有新版本时才下载。

**具体能力：** 保存订阅名称、资源地址和检查频率，显示最后检查、变化依据与错误；发现变化后通知，用户可选择自动创建新版本任务。

**用户收益：** 减少手动访问和比对，形成可追溯的资源版本记录。

**首版范围：** 仅明确添加的 HTTP／HTTPS 单文件直链，默认只检查并通知；自动下载需逐订阅开启。首轮以变化提示为主，保留旧文件，不覆盖历史版本。弱／缺失 validator 时显示无法确认；签名 query 变化本身不等于资源内容更新。应用退出期间不运行，启动后每个订阅最多补一次检查，不补齐所有遗漏周期。

**实现依赖：** 独立持久化检查计划、服务端条件请求、幂等资源版本键、退避和重试预算、统一网络／凭据策略。需要显式区分“资源发生变化”与“身份验证失败”，不能反复下载登录错误页面。

**复杂度估计：高。** 长期状态、认证过期、版本识别和网络使用需要可观测且有界的行为。

**验收标准：** 未变化不创建任务；同一变化多次检查只生成一个任务；时钟变化、休眠重启、429、认证失效和无 validator 均有明确结果；失败不破坏已下载版本；关闭订阅后不再产生请求。

### FE-14：本地 CLI

**当前基础：** 已有 Tauri 命令、任务模型、调度器、事件和 Native Messaging host。后者服务于浏览器交接，不是稳定的用户 CLI；主审计 `FUN-19` 和路线图仍将正式自动化接口列为边界。依据：[lib.rs](../src-tauri/src/lib.rs)、[tasks/actions.rs](../src-tauri/src/commands/tasks/actions.rs)、[events/mod.rs](../src-tauri/src/events/mod.rs)。

**适用场景：** 开发脚本提交模型／镜像下载，等待任务完成后继续处理；终端用户查询和批量暂停自己的任务。

**具体能力：** 创建、查询、暂停、恢复、重试、取消和等待完成；提供人类可读输出、结构化 JSON、稳定退出码和明确版本信息。后续再增加事件订阅与更多管理动作。

**用户收益：** 将下载器接入现有脚本工作流，保留统一的下载、限速、恢复与诊断能力。

**首版范围：** 同一 OS 用户控制正在运行的桌面实例；实例未运行时明确报错，不另启一个直接写同一 DB 的下载服务。优先使用受 OS 用户权限保护的本地 IPC，不开启远程监听。默认取消任务保留文件，删除文件操作先不开放。支持请求身份避免脚本重试造成重复创建。

**实现依赖：** 把可复用业务操作与依赖 AppHandle 的 UI 包装适度分离；稳定协议版本、请求／响应、错误码、授权、超时和分页输出。UI、CLI 和浏览器入口复用业务规则，同时保留各入口不同的权限边界；CLI 不能绕过逐任务锁直接修改 SQLite。

**复杂度估计：高。** CLI 文本解析较小，主要成本是跨平台本地通信、稳定兼容性和应用服务边界。

**验收标准：** UI 与 CLI 对相同任务操作产生一致状态；实例未启动、应用退出、请求超时、取消等待、重复请求、并发删除均有确定结果；JSON 和退出码可供脚本稳定处理；其他用户不能连接；命令行、shell 历史及输出不要求暴露明文凭据。

### FE-15：分片级修复

**当前基础：** HTTP 已有分段计划与精确 Range，BT 有协议内 piece 校验，其他路径有整文件 checksum 和完整性报告。下载段边界、失败的整文件 hash、缺少远端校验的本地摘要，都不能自动成为可信的损坏位置证据。依据：[checksum.rs](../src-tauri/src/download/checksum.rs)、[HTTP worker](../src-tauri/src/download/http/segmented/worker.rs)、[bt.rs](../src-tauri/src/download/bt.rs)。

**适用场景：** 一个超大文件局部损坏，用户有可信的分块摘要，希望只重新获取异常范围。

**具体能力：** 比较可信分片摘要、定位损坏区间、验证远端资源仍匹配、估算修复流量与磁盘成本，再下载并校验异常范围，最后执行整体确认与安全发布。

**用户收益：** 在可证明安全的前提下减少重新下载的数据量，尤其适合镜像、模型与大型数据集。

**首版范围：** 先做技术验证：HTTP／HTTPS 单文件，加明确来源和版本的可信分片清单；通过验证后再开放产品入口。仅有整文件 SHA-256 时显示“无法定位损坏范围”。首版使用独立修复副本保留原文件，明确可能仍需接近一份完整文件的额外空间；BT 优先使用自身 piece recheck 合同，不把 HTTP 修复逻辑套到 BT 文件上。

**实现依赖：** 可信分片元数据、远端身份、精确 Range 校验、修复作业所有权、磁盘预算与原子提交。不能把抽样一致当作全文件一致，也不能为节省磁盘直接在唯一副本上无恢复记录地修补。多镜像必须证明资源一致。

**复杂度估计：高。** 最大前提是可信校验数据的可获得性，其次是崩溃一致性和修复后验证。

**验收标准：** 定点破坏首／中／末分片后仅请求必要范围，最终文件字节正确；篡改的分片清单、远端替换、错误 Content-Range 与不支持 Range 均被拒绝；修复中取消或崩溃后原文件仍在；没有可信分片依据时不提供误导性的局部修复承诺。

## 6. 建议实施顺序与依赖

### 6.1 首批五项的交付顺序

首批组合为 FE-01、FE-03、FE-04、FE-02、FE-05。前面三项减少操作成本，后面两项降低大文件失败损失；“首批”表示优先投入和验证，不意味着不顾依赖一次性上线。

| 工作线 | 建议次序 | 可以独立推进的工作 | 必须先完成的前置 |
| --- | --- | --- | --- |
| 配置复用 | FE-01 任务预设 → FE-03 批量编辑 | 预设管理和批量结果 UI 可分别设计，复用字段组件 | 统一草稿与 patch 语义；复核 `R26-U01`、`R26-U03`、`R26-F01`，避免配置展示正确而真实探测不同 |
| 查询效率 | FE-04 保存筛选视图 | 可与配置、恢复和磁盘工作线并行，首版只用已有查询条件 | 维持查询版本／分页一致性；全集操作另行实现，不能冒充“全选所有匹配” |
| 大文件恢复 | FE-02 更换失效链接 | 资源身份决策与服务器 fixture 可先推进 | 凭据／代理探测一致、任务暂停排空、来源更新失败可回退；复核 `R26-F01` 与文件提交候选 `R26-A01` |
| 空间保护 | FE-05 磁盘空间预算 | 空间估算接口、卷识别与只读计划预览可先推进 | artifact 所有权、暂停原因、预算释放与重建；先覆盖单文件，再纳入 remux 等阶段峰值 |

FE-06 文件位置管理放在文件提交和恢复前置完成之后，它同时支撑 FE-12 的归档流程。FE-07 分组在批量结果模型稳定后加入；集合总限速、集合完成动作后续单独验收。

### 6.2 后续与中长期安排

## 7. 实现边界与共用验收标准

### 7.1 模型、接口与数据流

预设、保存视图、集合和检查计划需要版本化持久化模型；来源替换、文件迁移、分片修复与完成流程需要明确的操作状态和恢复记录。先确定各自首版合同，再增加所需 migration 和 IPC，避免为远期功能一次性扩张所有任务字段。

前端只表达用户意图并展示后端结果。路径预留、资源身份、调度资格、凭据读取、预算与文件操作由后端统一裁决；后续 CLI 复用相同业务路径。Rust 模型／命令变化使用 Specta 生成绑定，不能为新页面手写第二套 IPC 类型。

不同入口应保留现有边界：浏览器 handoff 仍只接受 HTTP／HTTPS，拒绝嵌入凭据，浏览器不能决定本地路径；本地用户可通过应用选择目录。所有网络路径遵守统一代理、SSRF、重定向和凭据源域策略。新增配置层必须保留继承、关闭和自定义代理的原有语义；自定义代理失败时不得静默回退直连。

任务凭据继续沿用现有加密存储。candidate／release 扩展保持最小权限、手动交接；自动接管和 Cookie／header 转发仍限 dev 实验能力，转发须显式启用、受白名单限制，持久化时加密。本文的新增功能不构成扩大浏览器权限或开放浏览器本地文件操作的授权。

### 7.2 交互与文案

- 创建或改变任务前显示最终有效配置、作用范围和关键后果；高级选项按需展开。
- 每个异步操作都有加载、失败、部分成功和结束状态。取消究竟停止执行、保留已成功项目还是仅关闭窗口，必须可见且一致。
- 批量操作保存完整逐项结果；更换链接、迁移或修复发生失败时，不能只留一个瞬时 Toast。
- 主要流程可用键盘完成，焦点与错误关联正确；保持亮暗主题、窄窗口和 reduced-motion 支持。
- Rust 返回稳定错误码和参数，前端完成本地化；新增文案更新全部 7 locale，不因 key 齐全宣称母语质量已验收。

### 7.3 正确性、性能与兼容性

- 文件操作覆盖同名竞争、跨卷、磁盘满、权限拒绝、取消及进程退出；至少保留可验证的原文件或明确的恢复路径。
- 资源身份不确定时禁止静默拼接；只有整文件摘要时不得声称可定位损坏分片。资源的源域、凭据作用域、任务 ID 和文件所有权分别验证。
- 计划、分组、策略和 CLI 共用现有 scheduler，不通过直接修改数据库或第二套 worker 绕过任务锁与取消收敛。
- 长期功能必须有查询／采样／网络预算；分页、虚拟化和缓存容量有界。未知空间、未知大小、未知瓶颈显示未知。
- 配置升级、旧备份导入和应用重启后不丢已有任务；新增格式不支持时返回可解释结果。预设和报告不导出密码、Cookie、私钥或完整敏感链接。
- 完成状态分清“传输结束”“校验通过”“后处理完成”；所需校验／归档仍在执行时不触发最终关机动作。

### 7.4 实施时的检查要求

每项功能先写与上文验收标准对应的场景测试。前端行为至少执行 `pnpm typecheck`、`pnpm test:frontend`，UI／打包变更执行 `pnpm build`；新增文案执行 `pnpm check:i18n`。Rust 命令／模型变化执行 `pnpm specta`、`pnpm check:bindings`，下载与恢复逻辑在 `src-tauri/tests` 增加真实 fixture 或故障注入测试。

合并候选执行 `pnpm verify` 及相应平台检查；涉及浏览器和相关说明时执行扩展构建验证。跨平台真实文件、时区、电源／网络事件、本地 IPC 与安装包验收分别留证据，不能由浏览器 mock 或一项编译通过替代。
