# Vibe Downloader 功能设计文档

## 1. 产品定位

Vibe Downloader 是一款基于 Tauri + React + Rust 的现代下载管理器，目标是在日常下载体验、速度调度、任务可靠性和界面质感上超过传统 IDM 类工具。

核心原则：

- 下载要快，但不能靠盲目堆线程。
- 下载要稳，崩溃、断网、重启后任务应可恢复。
- 下载要可理解，用户能知道慢在哪里、失败为什么。
- UI 要现代、清爽、高信息密度，适合长期常驻使用。
- React 只负责 UI，Rust 负责下载、调度、持久化和事件推送。

一句话目标：

> 用户一眼知道下载是否健康，软件自动跑满可用带宽，异常后能可靠恢复。

## 2. 目标用户

主要用户：

- 经常下载大文件的 Windows 桌面用户。
- 需要浏览器一键下发任务的日常用户。
- 对下载速度、断点续传、任务恢复有明确要求的用户。
- 对老式下载器 UI 和交互体验不满意的用户。

典型场景：

- 下载系统镜像、开发工具、游戏安装包、模型文件、压缩包。
- 浏览器中点击下载链接后，希望交给下载器统一管理。
- 家庭或办公网络中，需要全局限速，避免影响其他设备。
- 网络波动、断电、应用崩溃后，希望无需重新下载。

## 3. 产品体验目标

### 3.1 快

速度体验不只看峰值，还要看持续稳定性。

功能要求：

- 支持 HTTP Range 多连接下载。
- 支持动态连接数调整。
- 支持分块直写目标文件，下载完成后无需合并。
- 支持全局限速、单任务限速、任务并发上限。
- 支持按 host 控制连接数，避免触发服务器限流。
- 小文件自动使用单连接，避免过度调度。

用户可感知状态：

- 正在提速。
- 已达到服务器上限。
- 受全局限速影响。
- 服务器不支持多连接。
- 磁盘写入较慢。
- 网络波动，正在重试。

### 3.2 稳

可靠性是下载器的信任基础。

功能要求：

- 任务状态持久化到 SQLite。
- 每个分块的下载进度可恢复。
- 应用崩溃或系统重启后自动恢复未完成任务。
- 暂停、继续、取消、删除状态明确。
- 下载中使用临时文件后缀，完成后原子 rename。
- 续传前校验 `ETag`、`Last-Modified`、`Content-Length`。
- 服务器文件变化时阻止错误续传。
- 磁盘满、权限失败、文件被占用时提供明确错误原因。

### 3.3 顺手

日常使用应尽量少打扰。

功能要求：

- 浏览器扩展一键下发任务。
- 新任务弹出轻量确认，可配置默认下载目录。
- 支持按文件类型自动分类保存。
- 支持任务搜索、筛选、排序和批量操作。
- 支持打开文件、打开目录、复制链接、重新下载。
- 支持系统托盘常驻。
- 支持下载完成通知。

### 3.4 好看

UI 采用 Fluent-inspired + Geek Chic 的组合风格，兼顾大众审美、现代桌面质感和专业下载工具的信息密度。

默认界面应让普通用户觉得干净、顺手、可信；展开详情后再让高阶用户看到分块、连接、限速、磁盘 I/O 等引擎细节。视觉吸引力应来自精致层次、流畅反馈和关键状态的高能表达，而不是常态下的强装饰。

设计方向：

- 默认跟随系统深浅色。
- Windows 上优先贴近 Fluent 视觉语言。
- 暗色主题作为重点打磨方向，但不牺牲浅色主题可用性。
- 使用 Mica / 类 Mica 背景作为窗口层次，毛玻璃只用于顶栏、侧栏、命令面板和浮层。
- 主体任务列表保持高密度、可扫视，视觉上有卡片质感，但交互上仍以列表为主。
- 状态色克制使用，重点突出下载中、完成、失败、暂停、受限和高速峰值。
- 高速下载、满负荷并发、完成瞬间可以使用更有科技感的高能色彩和微动效。
- 暂停、排队、低优先级任务应退到低饱和灰度，降低视觉噪音。
- 图标按钮优先，文本按钮只用于明确命令。
- 速度、时间、文件大小、连接数等跳动数据使用等宽数字或 `tabular-nums`，避免 UI 抖动。

## 4. MVP 范围

第一阶段只做 HTTP 下载，把核心体验做稳。

MVP 必须包含：

- 新建 HTTP 下载任务。
- 自动探测文件名、大小、Range 支持。
- 多连接分块下载。
- 分块直写。
- 暂停和继续。
- 崩溃恢复。
- 全局任务队列。
- 全局限速。
- 活跃任务并发上限。
- 下载完成后打开文件或目录。
- 任务列表、任务详情、基础设置。
- 浏览器扩展通过 Native Messaging 下发任务。

MVP 暂不包含：

- BT 下载。
- HLS 下载。
- 网盘解析。
- 视频嗅探。
- 跨设备同步。
- 云端账号。

## 5. 核心功能设计

## 5.1 HTTP 下载任务

### 创建任务

输入来源：

- 用户在 App 内粘贴 URL。
- 浏览器扩展下发 URL。
- 命令行或系统协议后续接入。

创建流程：

1. Rust 发送 `HEAD` 请求探测资源。
2. 如 `HEAD` 不可靠，降级使用带 Range 的 `GET` 探测。
3. 获取文件名、文件大小、MIME 类型、Range 支持情况。
4. 生成下载计划。
5. 写入 SQLite。
6. 进入队列或立即开始。

探测字段：

- URL。
- 最终重定向 URL。
- `Content-Length`。
- `Content-Disposition`。
- `Accept-Ranges`。
- `ETag`。
- `Last-Modified`。
- `Content-Type`。

### 下载模式

支持两种模式：

- 单连接下载：用于小文件或不支持 Range 的服务器。
- 多连接下载：用于支持 Range 的大文件。

默认策略：

- 小于 16 MB：单连接。
- 16 MB 到 256 MB：最多 4 连接。
- 256 MB 到 2 GB：最多 8 连接。
- 大于 2 GB：最多 16 连接。

具体连接数由动态调度器调整，不直接固定。

## 5.2 分块直写

目标：

下载完成后无需合并文件。

流程：

1. 创建临时文件，例如 `filename.ext.vibe-downloading`。
2. 如果文件大小已知，预分配目标大小。
3. 将文件切分为多个 byte range。
4. 每个连接下载自己的 range。
5. 每个 range 使用随机写入写到目标偏移。
6. SQLite 记录每个分块的 `downloaded_until`。
7. 所有分块完成后进行完整性检查。
8. 原子 rename 为最终文件名。

分块字段：

- `task_id`
- `range_start`
- `range_end`
- `downloaded_until`
- `status`
- `retry_count`
- `last_error`

注意事项：

- 不在目标文件中写入元数据。
- 不生成多个 part 文件。
- 元数据和下载文件分离。
- 写入进度需要节流保存，避免频繁刷盘。

## 5.3 动态多连接

动态连接不以“线程越多越快”为原则，而是以单位连接收益为依据。

决策周期：

- 默认每 3 到 5 秒评估一次。

增加连接条件：

- 当前任务未达到单任务连接上限。
- 当前 host 未达到 host 连接上限。
- 最近几个周期总速度仍有增长空间。
- 新连接预计不会被全局限速压制。
- 服务器没有返回明显限流信号。

减少连接条件：

- 新增连接后总速度没有提升。
- 某些连接长期低速。
- 服务器返回 `429`、`403`、`5xx`。
- 出现频繁超时或连接重置。
- 全局限速已成为瓶颈。

连接健康指标：

- 当前速度。
- 平均速度。
- 首包耗时。
- 超时次数。
- 重试次数。
- 最近错误。

对用户展示：

- 当前连接数。
- 连接数变化原因。
- 是否受服务器限制。
- 是否受全局限速影响。

## 5.4 断点续传与崩溃恢复

恢复流程：

1. 应用启动时扫描未完成任务。
2. 读取 SQLite 中的任务和分块状态。
3. 对每个可恢复任务重新探测远程资源。
4. 校验远程资源是否与原任务一致。
5. 一致则继续未完成 range。
6. 不一致则进入“需要用户处理”状态。

续传校验：

- `Content-Length` 必须一致。
- 强 ETag 必须一致。
- 如只有弱 ETag，需要结合 `Last-Modified` 判断。
- `Last-Modified` 变化时默认阻止自动续传。
- 服务器不再支持 Range 时，提示重新下载。

异常状态：

- 远程文件已变化。
- 本地临时文件不存在。
- 本地临时文件大小异常。
- 保存目录不可写。
- 磁盘空间不足。
- 文件被其他进程占用。

## 5.5 限速与队列

限制层级：

- 全局下载速度。
- 单任务下载速度。
- 全局活跃任务数。
- 单任务连接数。
- 单 host 连接数。

调度原则：

- 全局 token bucket 控制总速度。
- 活跃任务优先级可调整。
- 队列中任务按优先级和创建时间排序。
- 暂停任务不占用活跃并发。
- 失败后自动重试，但有最大重试次数。

任务优先级：

- 高。
- 普通。
- 低。

## 5.6 浏览器扩展与本机通信

目标：

浏览器是最高频入口，必须优先支持。

扩展能力：

- 右键菜单“使用 Vibe Downloader 下载”。
- 下载链接捕获。
- 当前页面链接发送到 App。
- 可选：检测大文件下载并询问是否接管。

通信方式：

- Chrome / Edge / Brave / Opera / Vivaldi / Chromium 使用同一套 Chromium WebExtension 开发包。
- Firefox 使用同源 WebExtension 逻辑与 Firefox Native Messaging manifest。
- Safari 仅 macOS，使用 Safari Web Extension 包装，生产交付单独处理。
- Native Messaging 是阶段 5 主通道；Localhost / WebSocket 后置到实时浏览器面板或本地 API。
- 独立 `vibe-native-host` 负责 stdin/stdout Native Messaging 协议，不让 Tauri GUI 主进程接管标准输入输出。
- App 未运行时由 native host 启动；App 已运行时通过 single-instance 转发第二次启动参数。
- App 注册/卸载 Native Messaging manifest，并在设置页展示每个浏览器状态。

消息内容：

- URL。
- 页面 URL。
- Referer。
- User-Agent。
- 建议文件名。
- request id，用于去重和日志关联。

安全限制：

- 网页不能直接指定任意本地路径。
- 阶段 5 只接受 `http` / `https` URL。
- 嵌入账号密码的 URL 会被拒绝。
- Cookie 和敏感 header 不在阶段 5 转发。
- 默认保存目录由 App 设置决定。
- 每次 handoff 写入 `browser_messages`，用于 request id 去重和失败诊断。

## 5.7 插件化协议

第一阶段只内置 HTTP，但需要保留协议扩展边界。

插件统一能力：

- 判断是否能处理 URL。
- 探测资源。
- 创建下载计划。
- 接收调度上下文。
- 推送状态事件。
- 支持暂停、继续、取消。

不强行统一的数据模型：

- HTTP 使用 byte range。
- HLS 使用媒体 segment。
- BT 使用 piece。

统一的数据模型：

- 任务状态。
- 速度统计。
- 限速。
- 队列。
- 错误事件。
- UI 展示事件。

## 6. UI 功能设计

整体 UI 采用“双层体验”：

- 大众默认层：第一眼清楚、好看、低负担。默认只展示文件名、来源、进度、速度、剩余时间、状态和常用操作。
- 专业增强层：用户展开详情后，展示分块热力图、连接健康、Range 状态、重试记录、服务器限速、磁盘写入等引擎信息。

视觉原则：

- 常态安静，异常和高速状态才增强视觉反馈。
- 主要操作要熟悉，使用标准按钮、菜单、标签页、命令面板和导航结构。
- 技术细节可以可视化，但不直接压到默认视图里。
- 颜色承担状态含义，不做无意义装饰。
- 动效承担状态变化，不做页面表演。
- 图标需要 tooltip 或文本语义，不能只靠图形让用户猜。

限制项：

- 不使用大面积毛玻璃覆盖任务列表。
- 不把主任务区做成默认卡片网格。
- 不让霓虹色成为常态主题。
- 不为所有状态变化添加弹簧动画。
- 不让高阶术语成为普通用户完成下载的前置条件。

## 7. 事件与状态同步

React 不应频繁 invoke Rust 查询进度。Rust 下载核心主动推送聚合事件。

事件类型：

- `task.created`
- `task.started`
- `task.progress`
- `task.paused`
- `task.completed`
- `task.failed`
- `task.retrying`
- `task.health_changed`
- `connection.changed`
- `queue.changed`
- `settings.changed`

进度推送策略：

- 默认每 250 ms 聚合推送一次。
- 后台窗口可降低到每 1000 ms。
- 单个连接内部进度不直接推给 UI。
- UI 只接收任务级聚合数据和详情页需要的连接摘要。

## 9. 错误体验设计

错误文案必须具体、可操作。

示例：

```text
服务器不支持断点续传，此任务只能从头下载。
```

```text
远程文件已变化，为避免文件损坏，已停止续传。你可以重新下载或另存为新文件。
```

```text
磁盘空间不足，释放至少 2.4 GB 后可继续。
```

```text
文件被其他程序占用，关闭占用程序后重试。
```

错误状态应提供操作：

- 重试。
- 重新下载。
- 另存为。
- 打开目录。
- 复制错误详情。

## 10. 非功能要求

性能：

- UI 在 1000 个历史任务下仍保持流畅。
- 活跃下载任务进度更新不应导致 React 大面积重渲染。
- SQLite 写入需要批量节流。
- 文件写入不得阻塞 UI 线程。

可靠性：

- 应用异常退出后任务状态可恢复。
- 断网后任务进入等待状态。
- 数据库损坏需要备份与恢复策略。
- 下载完成前不暴露最终文件名。

安全：

- 浏览器扩展不能指定任意本地路径。
- 不默认展示敏感 header。
- 本机通信需要来源校验。
- 下载路径需要防路径穿越。

可维护性：

- Rust 下载核心独立于 UI。
- 协议处理与调度器分离。
- UI 状态与下载状态通过事件同步。
- 插件协议接口提前预留，但 MVP 不过度抽象。

## 12. 成功标准

第一版成功标准：

- 下载大文件时速度稳定，连接数调整有实际收益。
- 应用崩溃后，未完成任务可以继续。
- 暂停和继续不会损坏文件。
- 不支持 Range 的服务器能正确降级。
- 浏览器扩展可以稳定下发任务。
- 用户能清楚知道任务为什么慢或为什么失败。
- UI 比传统下载器更现代，但不牺牲任务管理效率。
