# Vibe Downloader UI 设计风格文档

## 1. 风格定位

Vibe Downloader 的 UI 风格是 Fluent-inspired + Geek Chic。

它不是传统下载器的工具栏堆叠，也不是纯极客风的仪表盘。默认状态面向大众用户，强调好看、清楚、顺手、可信；展开详情后面向高阶用户，展示下载引擎的真实工作状态。

核心表达：

- 常态安静。
- 高速时有能量。
- 异常时可诊断。
- 操作路径熟悉。
- 高阶信息可展开。

## 2. 设计哲学

## 2.1 Silent Power

软件是工具，不应抢走用户注意力。

常态下：

- 任务列表保持低噪音。
- 颜色以中性灰和单一主色为主。
- 暂停、排队、低优先级任务主动降低视觉权重。
- 下载器可以常驻，不让用户觉得屏幕被打扰。

需要增强反馈时：

- 高速下载。
- 下载完成。
- 服务器限速。
- 磁盘空间不足。
- 续传不可用。
- 用户需要决策。

这些时刻可以使用更明确的颜色、微动效和信息条。

## 2.2 Mainstream First

默认体验必须贴近大众审美。

普通用户不应该先看到复杂的线程、Range、Chunk、I/O 术语。默认视图只回答几个问题：

- 正在下载什么？
- 下了多少？
- 速度多快？
- 还要多久？
- 是否正常？
- 我现在能做什么？

高阶数据不删除，只放到展开详情里。

## 2.3 Geek Chic

复杂底层逻辑应该被美化为有用的可视化，而不是用原始日志压给用户。

适合可视化的内容：

- 分块下载进度。
- 当前连接数。
- 每个连接的速度。
- 重试和超时。
- 服务器是否支持 Range。
- 是否可断点续传。
- 磁盘写入是否拖慢下载。

默认说人话，详情给证据。

示例：

```text
默认视图：服务器限速中
详情视图：8 个连接中 5 个低速，最近 3 次请求返回 429
```

## 2.4 Keyboard Efficient

键盘效率是高级体验，但不能牺牲鼠标用户。

必须支持：

- `Ctrl/Cmd + K` 打开命令面板。
- 粘贴 URL 后回车创建任务。
- 搜索任务。
- 暂停全部。
- 继续全部。
- 切换限速。
- 打开当前任务文件夹。
- 删除或重试选中任务。

命令面板是加速路径，不是唯一入口。所有主要功能都应在 UI 中可发现。

## 3. 视觉系统

## 3.1 主题

默认跟随系统主题。

暗色主题是重点打磨方向：

- 适合长期后台常驻。
- 适合夜间或开发环境。
- 更能承载速度感和引擎可视化。

浅色主题不能只是反色：

- 需要保持任务列表边界清晰。
- 状态色要降低刺眼程度。
- 玻璃效果应更轻。

## 3.2 背景与层次

推荐层级：

```text
窗口背景
  侧栏 / 顶栏
  任务列表主体
  右侧详情面板
  浮层 / 命令面板
```

使用原则：

- 顶栏、侧栏可以使用 Mica 或类 Mica 质感。
- 命令面板和浮层可以使用轻量毛玻璃。
- 任务列表主体使用清晰的实色背景。
- 不在 dense text 下方使用强 blur。
- 不做嵌套玻璃卡片。

## 3.3 色彩

基础色：

- 极深灰蓝或深中性灰作为暗色背景。
- 非纯黑，避免死黑屏幕感。
- 非纯白，浅色主题也需要轻微冷色调。

状态色：

- 下载中：主色或电光蓝。
- 高速峰值：霓虹绿或青绿色，仅短暂出现。
- 完成：绿色，但保持克制。
- 失败：红色，必须高可识别。
- 警告：琥珀色。
- 暂停和排队：灰度低饱和。

霓虹色使用规则：

- 只在活跃速度、峰值、完成瞬间、热力图重点状态中使用。
- 不作为大面积背景。
- 不同时让多个高饱和颜色抢占主界面。

## 3.4 字体

界面字体：

```css
Inter, "Segoe UI Variable", "Segoe UI", system-ui, sans-serif
```

数据字体：

```css
"Geist Mono", "JetBrains Mono", "Cascadia Mono", ui-monospace, monospace
```

数字要求：

```css
font-variant-numeric: tabular-nums;
```

必须使用等宽数字的内容：

- 下载速度。
- ETA。
- 文件大小。
- 进度百分比。
- 连接数。
- 已下载字节数。

目标是避免实时刷新时 UI 宽度抖动。

## 4. 布局规范

## 4.1 主界面

推荐结构：

```text
自定义标题栏 / 命令栏
左侧导航 + 中间任务列表 + 右侧详情面板
底部全局状态栏
```

主界面优先展示任务，不做欢迎页或营销页。

## 4.2 任务列表

默认任务视图采用高密度列表，不采用大卡片网格。

任务行展示：

- 文件图标。
- 文件名。
- 来源域名。
- 进度条。
- 当前速度。
- ETA。
- 已下载 / 总大小。
- 状态。
- 快捷操作。

任务行可以有轻微卡片质感：

- 细边线。
- 轻背景。
- hover 提升。
- 选中状态明确。

但不应变成大面积卡片墙。

## 4.3 详情面板

任务详情使用渐进展开。

默认显示：

- 文件名。
- 保存路径。
- 下载进度。
- 速度。
- 是否可续传。
- 健康状态。

高级 tabs：

- 概览。
- 分块。
- 连接。
- 日志。
- 请求。

## 4.4 窄窗口模式

窄窗口可以转为单列 compact card。

要求：

- 不丢失核心状态。
- 快捷操作仍然可达。
- 详情改为抽屉或独立面板。
- 底部状态栏可压缩为总速度和活跃任务数。

## 5. 组件风格

## 5.1 命令栏

命令栏承载常用操作：

- 新建任务。
- 开始。
- 暂停。
- 删除。
- 限速。
- 搜索。
- 设置。

按钮优先使用图标，复杂命令进入菜单。

## 5.2 命令面板

命令面板是高级效率中心。

支持：

- 粘贴 URL 创建任务。
- 搜索任务。
- 输入命令。
- 运行批量操作。
- 快速进入设置项。

视觉上可使用轻量玻璃和强聚焦背景，但必须保持文字清晰。

## 5.3 分块热力图

分块热力图是 Geek Chic 的核心视觉资产。

状态建议：

- 未开始：低饱和灰。
- 下载中：主色。
- 高速：高能色。
- 完成：稳定绿色或主色完成态。
- 失败：红色。
- 重试：琥珀色。

要求：

- 不只靠颜色表达状态。
- hover 显示 range、速度、重试次数。
- 旁边提供文本摘要。

## 5.4 进度条

进度条要精细，不要厚重。

规则：

- 默认细线。
- 下载中平滑插值。
- 暂停时降低饱和度。
- 错误时停止动画并显示原因。
- 高速峰值可加入轻微能量光效。

## 5.5 信息条和错误

错误提示使用 InfoBar 或内联状态，不优先使用阻塞 modal。

文案必须具体：

```text
远程文件已变化，为避免文件损坏，已停止续传。
```

```text
磁盘空间不足，释放至少 2.4 GB 后可继续。
```

每个错误应提供可操作按钮：

- 重试。
- 重新下载。
- 另存为。
- 打开目录。
- 复制详情。

## 6. 动效规范

动效服务状态，不服务表演。

适合动效：

- 打开命令面板。
- 展开任务详情。
- 下载完成反馈。
- 任务排序移动。
- 进度平滑推进。
- 错误状态吸引注意。

不适合动效：

- 每个数字跳动。
- 大量列表项持续闪烁。
- 页面加载编排动画。
- 让用户等待的慢弹簧。

建议时间：

- 普通状态变化：150 到 250 ms。
- 命令面板：120 到 180 ms。
- 详情展开：180 到 260 ms。
- 真实下载事件：Rust 每 250 到 500 ms 聚合推送，UI 自己做插值。

## 7. 可访问性要求

- 所有功能必须键盘可达。
- 焦点状态必须明显。
- 图标按钮必须有 tooltip 和 accessible label。
- 颜色不能作为唯一状态表达。
- 热力图必须有文本摘要。
- 主要文字满足 WCAG AA 对比度。
- 命令面板不能取代可见导航。

## 8. 明确禁止项

- 不使用纯黑或纯白作为大面积背景。
- 不使用大面积毛玻璃覆盖任务列表。
- 不使用默认大卡片网格作为任务管理主视图。
- 不使用渐变文字。
- 不使用常态霓虹主题。
- 不使用重复的营销式指标卡片。
- 不使用无意义动效。
- 不让普通用户必须理解 Chunk、Range、I/O 才能完成下载。

## 9. 设计验收标准

第一版 UI 达标条件：

- 用户 5 秒内能看懂如何新建下载。
- 任务列表在 100 个任务下仍然容易扫视。
- 下载速度数字刷新时不抖动。
- 高速状态有视觉吸引力，但不干扰阅读。
- 失败状态能清楚说明原因和下一步。
- 鼠标用户和键盘用户都有完整操作路径。
- 默认界面大众友好，详情界面专业可信。
