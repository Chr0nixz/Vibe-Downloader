# Vibe Downloader 国际化与翻译规范指南 (i18n Style Guide)

本文档是 Vibe Downloader 项目多语言翻译与本地化维护的权威规范。旨在消除机翻腔、统一核心协议与下载专业术语、规范复数形式与占位符，并为项目支持的 7 种语言提供明确的行文标准。

---

## 一、 语言支持等级与架构契约

Vibe Downloader 目前支持 7 种语言，划分为两种保障等级：

| 语言代码 | 语言名称 | 支持等级 | 自动检测 (UX-1) | 维护要求 |
| :--- | :--- | :---: | :---: | :--- |
| **`en`** | English (US) | **Stable (基准)** | 是 (默认回退) | 核心基准源，所有新功能/新字段的首发语言 |
| **`zh-CN`** | 简体中文 | **Stable (稳定)** | 是 | 核心稳定语言，提供 100% 深度地道翻译与严格校对 |
| **`zh-TW`** | 繁體中文 | Beta | 否 (回退 en) | 遵循台湾/港澳正体中文本地化习惯，禁止机械简转繁 |
| **`ja`** | 日本語 | Beta | 否 (回退 en) | 标准计算机日文、片假名外来语与自然敬体 |
| **`ko`** | 한국어 | Beta | 否 (回退 en) | 标准计算机韩文与自然敬语 |
| **`ru`** | Русский | Beta | 否 (回退 en) | 严格遵守俄语四类 CLDR 复数屈折规范 |
| **`es`** | Español | Beta | 否 (回退 en) | 遵循西语正字法与动词时态习惯 |

### 核心契约与安全规则
1. **基准唯一性**：`src/i18n/locales/en.ts` 是全局键集合与结构的唯一定义源，禁止在非英文语言包中单独发明新键。
2. **插值占位符保护**：所有 `{{placeholder}}` 变量（如 `{{speed}}`、`{{time}}`、`{{bytes}}`、`{{count}}`）必须原样保留，禁止翻译、篡改拼写或增删花括号。
3. **错误码与诊断解耦 (UX-11)**：后端 Rust 抛出的底层技术错误信息（包含原始堆栈或路径）仅允许进入“诊断”面板；UI 提示框、任务错误横幅必须使用已本地化的稳定错误码（`errors.*`）。

## 二、 核心术语与多语言对照基准表 (Core Terminology Matrix)

下载软件涉及大量的网络底层、分片分段及 P2P 专用术语，各语言必须统一采用以下对照，严禁自由发挥或机翻直译：

| 英文原词 (EN) | 简体中文 (zh-CN) | 繁體中文 (zh-TW) | 翻译准则与反面案例避坑 |
| :--- | :--- | :--- | :--- |
| **Needs a decision / Needs attention** | **待处理** / **需要确认** | **待處理** / **需要確認** | ❌ **严禁直译为“需要决定”**。中文下载软件规范为“待处理”或“需要操作”。 |
| **Browser handoff** | **浏览器接管** / **浏览器转发** | **瀏覽器接管** / **瀏覽器轉發** | ❌ **严禁保留英文“浏览器 handoff”**。指浏览器插件将下载链接交由桌面端接管。 |
| **Staging / Staging directory** | **分段暂存** / **暂存目录** | **分段暫存** / **暫存目錄** | ❌ **严禁中英混杂“staging 目录”**。指分段下载合并前的临时工作空间。 |
| **Staging residue remains** | **存在未完全清理的暂存文件** | **存在未完全清理的暫存檔案** | ❌ **避免叠词语病“仍有暂存残留”**。语义清晰通顺。 |
| **Peer(s)** (BitTorrent) | **节点** / **连接节点** | **節點** / **連線節點** | ❌ **严禁与种子混淆**。若保留英文需加说明（如“节点 (Peer)”）。 |
| **Seed / Seeder** (BitTorrent) | **做种者** / **完整节点** | **做種者** / **完整節點** | ❌ **严禁与 .torrent 种子文件混同**。“做种者”指已拥有 100% 完整文件的传输者。 |
| **Seeding** (BitTorrent) | **做种** | **做種** | 指完成下载后持续为群体提供上传服务的行为。 |
| **Tracker announce** | **Tracker 宣告** | **Tracker 宣告** | ❌ **严禁漏译为“announce 列表”**。指客户端向 Tracker 服务器定期上报自身状态。 |
| **Task / Job** | **任务** | **任務** | 统一为“任务”，避免在同一界面混用“任务”与“工作”。 |
| **Resume (capability)** | **断点续传** / **支持续传** | **斷點續傳** / **支援續傳** | 描述服务器或协议能力时指 HTTP Range 续传。 |
| **Resume (action)** | **继续** / **开始** | **繼續** / **開始** | 针对任务控制动作，与“暂停”相对应。 |
| **Integrity passport** | **文件完整性凭证 (Passport)** | **檔案完整性憑證 (Passport)** | 首次出现或报告标题处保留说明，避免生硬直译“完整性护照”。 |
| **Single connection** | **单连接下载** / **不支持分段** | **單連線下載** / **不支援分段** | 描述无法通过并发加速、仅单流传输的下载。 |
| **Drawer** (UI Component) | **详情面板** / **侧边详情** | **詳細資訊面板** / **側邊詳細** | ❌ **严禁在用户文案中直译为“抽屉”**。界面组件术语应转化为产品功能词。 |
| **Native Messaging host** | **本机消息传递主机** | **原生傳訊主機** | 浏览器扩展与桌面客户端通信的本地 Native 宿主程序。 |

## 三、 复数规则与 CLDR 分流标准 (Pluralization & CLDR)

本项目严格采用基于 CLDR 标准的动态复数匹配（门禁验证规则 `FUN-22`），各语言的键结构必须遵循其语言学规律：

### 1. 无屈折复数语言 (`zh-CN`, `zh-TW`, `ja`, `ko`)
- **规律**：汉语、日语、韩语语法中没有单复数形态变化，数量词由量词（个/项/条）表达。
- **规范**：
  - 仅保留基础键（即相当于 CLDR 的 `other` 形式），**绝不能额外添加 `_one` 键**。
  - 例如：`toast.tasksDeleted: "已删除 {{count}} 个任务"`。

### 2. 具备二元单复数语言 (`en`, `es`)
- **规律**：区分单数（1）与复数（0, 2+）。
- **规范**：
  - 必须同时成对提供 `_one` 和基础键（`_other` 回退）。
  - 例如：`toast.tasksDeleted_one: "Deleted 1 task"`，`toast.tasksDeleted: "Deleted {{count}} tasks"`。

### 3. 四元屈折复数语言 (`ru`)
- **规律**：俄语按末位数字分为 `one` (1, 21..), `few` (2-4, 22-24..), `many` (5-20, 25-30..), `other`。
- **规范**：
  - 必须根据 CLDR 分支提供相应的后缀键，门禁脚本 `check:i18n` 会严格验证其可达性。

## 四、 分语言行文风格细则

### 1. English (`en`) —— 基准与产品调性
- **风格**：Dense, calm desktop utility（紧凑、克制、专业的现代桌面工具）。
- **句式**：短促有力，避免营销化用语（如 "Enjoy lightning download"）。使用准确的操作动词。
- **标点**：完整陈述句以英文句号 `.` 结尾；操作引导与列表项不加句号。

### 2. 简体中文 (`zh-CN`) —— 核心稳定
- **风格**：专业、现代、自然流畅，贴近资深开发与极客工具习惯。
- **标点规范**：
  - 必须使用全角中文标点（`，` `。` `：` `？` `（` `）` `【` `】`）。
  - 英文句末为 `.` 时，中文说明句末对应使用 `。`；标题和按钮标签不加句号。
  - 中文文案中若引用英文专有名词，名词两侧与中文字符之间保留半角空格（如：`支持 HTTP/HTTPS 协议`）。
- **去机翻准则**：
  - 严禁直译被动语态（如“被取消了”改为“已取消”）。
  - 严禁生硬英文名残留（如“在 settings 中配置”改为“在设置中配置”）。

### 3. 繁體中文 (`zh-TW`) —— Beta
- **风格**：使用台湾及正体中文用户习惯词汇。
- **典型词汇映射**：
  - 设置 $\to$ 設定
  - 网络 $\to$ 網路
  - 文件夹 $\to$ 資料夾
  - 默认 $\to$ 預設
  - 端口 $\to$ 連接埠
  - 内存 $\to$ 記憶體
  - 代理 $\to$ 代理伺服器 / Proxy

### 4. 日本語 (`ja`) —— Beta
- **风格**：现代桌面软件常用敬体（です/ます）与简洁提示体。
- **术语规范**：
  - 任务 $\to$ タスク
  - 下载 $\to$ ダウンロード
  - 校验码 $\to$ チェックサム
  - 做种 $\to$ シーディング / シード
  - 设置 $\to$ 設定

### 5. 한국어 (`ko`) —— Beta
- **风格**：符合 macOS / Windows 现代韩文应用标准。
- **术语规范**：
  - 任务 $\to$ 작업
  - 下载 $\to$ 다운로드
  - 暂存 $\to$ 임시 보관
  - 继续 $\to$ 재개
  - 暂停 $\to$ 일시 중지

## 五、 后端错误码与事件本地化流程 (Rust & Event Contracts)

为确保“无未翻译英文泄漏至用户界面”：

1. **Rust 错误码注册契约**：
   - 凡在 `src-tauri/` 中通过 `engine_error("new_code", ...)` 或 `AppErrorPayload::new("new_code", ...)` 抛出新错误码：
   - 必须在 `src/lib/stable-error-codes.ts` 的 `STABLE_ERROR_CODES` 中登记该错误码。
   - 必须在 `scripts/stable-error-messages.json` 和 `scripts/stable-error-causes.json` 中配置 7 种语言文案。
   - 必须运行 `node scripts/sync-stable-error-i18n.mjs` 自动同步并生成至所有语言包文件。
2. **任务历史事件本地化契约**：
   - 凡在 Rust 中写入 `task_events` 表的新 `event_type`，必须同步在各语言包的 `taskEvent.<event_type>` 补充对应文案，杜绝界面出现下划线原始英文。

## 六、 门禁与提交前自检清单 (Verification Checklist)

在任何翻译修改或文案新增提交前，必须顺序执行并全绿通过：

```bash
# 1. 静态检查：验证所有语言包的键集、占位符及未翻译英文句子
pnpm check:i18n

# 2. 单元测试：验证发布工具与 i18n 完整性单测
pnpm test:release-tools

# 3. 前端测试与类型断言：确保 TranslationKey 严格匹配
pnpm typecheck
pnpm test:frontend

# 4. 文档一致性检查：确保文档格式与版本一致
pnpm check:docs
```
